- 운영 기준점의 TBT와 모범 사례 경고 대부분은 Cloudflare `/cdn-cgi/challenge-platform/` 보안 스크립트에서 발생했다.

## 테스트 중 발견하고 수정한 오류

1. 처음 작성한 Next.js Metadata Route 파일이 vinext route table에 나타나지 않았다. Cloudflare 배포 호환성을 위해 `/robots.txt`, `/sitemap.xml`, `/manifest.webmanifest`를 명시적 Route Handler로 변경했고 production build에서 모두 `λ` 라우트로 확인했다.
2. manifest 링크는 `metadataBase` 적용으로 절대 URL이 생성됐다. 회귀 테스트를 실제 렌더링 결과에 맞게 수정했다.
3. 브랜드에 임의 `aria-label`을 붙이면 눈에 보이는 `止`와 접근성 이름이 다시 불일치했다. 화면 텍스트 자체를 접근성 이름으로 사용하도록 변경했고 Lighthouse 감사를 통과했다.

## 테스트 데이터 정리

- Supabase 통합 테스트가 생성한 책방·소식·원본·미리보기·편집 임대를 모두 정리했다.
- 운영 데이터를 직접 수정하지 않았다.
- `.env.local`과 비밀값은 Git 변경 및 보고서에 포함하지 않았다.

## 경고와 잔여 위험

- HEIC 변환기 1.3MB 청크는 기존과 같이 HEIC 선택 시에만 로드된다. 방문자 첫 화면에는 포함되지 않지만 실제 구형 모바일 HEIC 성능은 별도 TC가 남아 있다.
- Lighthouse가 요청을 일찍 닫을 때 로컬 vinext 서버에 `ERR_STREAM_UNABLE_TO_PIPE`가 기록됐다. 감사 결과와 사용자 응답에는 영향이 없었고 production 배포 후 Worker 로그에서 재확인한다.
- 운영 수치는 Cloudflare 보안 스크립트와 콜드 스타트에 따라 흔들릴 수 있다.

## 최종 결론

- P0 회귀와 Supabase 통합 테스트에 실패가 없고, SEO·접근성·지연 로드 변경도 production build에서 검증됐다.
- Sites 버전 저장까지 진행 가능하다. 공개 배포 후 운영 Lighthouse와 검색 라우트 스모크를 완료해야 최종 릴리스 검증이 끝난다.
