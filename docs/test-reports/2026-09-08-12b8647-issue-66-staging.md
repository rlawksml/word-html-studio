## 원인과 수정

vinext 0.0.50이 간접 의존성으로 취약한 `image-size@2.0.2`를 고정하고 있었고, 같은 안정 버전 계열에는 이를 제거한 릴리스가 없었다. 별도 이슈와 draft PR로 범위를 격리해 vinext 1.0.0-beta.9를 검증했다.

vinext만 단독으로 올린 첫 설치는 `@vitejs/plugin-rsc@^0.5.34` peer 조건 때문에 ERESOLVE로 안전하게 중단됐다. 필요한 peer만 0.5.34로 함께 고정했으며 `--force`는 사용하지 않았다. 결과 lockfile에서 `image-size`가 제거되고 전체 audit의 high 취약점이 0건이 됐다.

첫 전체 회귀에서 canonical root URL의 trailing slash와 manifest의 절대·상대 표현 차이로 75/76이 실패했다. 실제 URL 의미를 비교하도록 회귀 테스트를 보강한 뒤 SEO 집중 15/15와 전체 76/76을 통과했다.

후보 v13 공개 읽기 검증 뒤 작업자 암호 입력을 자동화하려 했지만, 브라우저 보안 정책상 password 필드는 일반 locator 입력으로 전달되지 않았다. 이 현상은 기존 v12에서도 동일하게 재현되어 vinext 회귀로 판정하지 않았다. 다만 P0 UAT 증거가 없으므로 후보를 병합하지 않고 Staging을 즉시 v12로 롤백했다.
