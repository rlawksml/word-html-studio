# v1.1 사용자 검증 시나리오

이 문서는 개발자가 아닌 실제 사용자가 Staging에서 v1.1 개선 사항을 순서대로 확인하는 체크리스트입니다. 예상 시간은 약 30~40분입니다.

## 1. 테스트 환경과 안전 규칙

- 테스트 주소: `https://bookstore-news-studio-staging.rlawksml.chatgpt.site/`
- 주소에 반드시 `-staging`이 들어 있는지 먼저 확인합니다.
- 운영 주소 `https://bookstore-news-studio.rlawksml.chatgpt.site/`에서는 이 시나리오를 실행하지 않습니다.
- 기존 책방과 기존 소식은 수정하거나 삭제하지 않습니다.
- 아래에서 정한 `[UAT-20260909]` 이름의 테스트 자료만 새로 만듭니다.
- 실패한 저장·업로드를 여러 번 반복하지 말고 한 번만 재현한 뒤 화면을 캡처합니다.
- 테스트가 끝나면 기존 데이터를 직접 정리하지 말고, 새로 만든 정확한 책방 이름을 Codex에 알려 안전하게 정리합니다.

결과는 다음 중 하나로 표시합니다.

- `PASS`: 기대 결과와 동일함
- `FAIL`: 실행됐지만 기대 결과와 다름
- `BLOCKED`: 암호·브라우저·네트워크 문제로 실행할 수 없음

### 검증 범위와 기존 TC 연결

| 사용자 확인 범위 | 연결된 TC |
|---|---|
| 입력자·HTML 편집자 로그인과 세션 | TC-AUTH-001, TC-AUTH-003 |
| 테스트 책방 저장 | TC-BOOK-001 |
| 달력 월 이동과 여러 날짜 | TC-SUB-010 |
| 장기 전시 기간 | TC-SUB-011, TC-DR-009 |
| 작성 중 URL 자동 저장 | TC-SUB-009 |
| 사진과 전용 드래그 손잡이 | TC-IMG-001~004, TC-SORT-001~002 |
| 마지막 한글과 입력 마무리 | TC-SUB-004, TC-SUB-008 |
| 방문자 달력·상세 | TC-PUBLIC-001~002 |
| HTML·TXT·사진 결과물 | TC-HTML-001~003 |

## 3. 시작 상태 확인

- [ ] Staging 주소를 열었을 때 로딩 화면이 사라지고 방문자 달력이 표시됩니다.
- [ ] 현재 화면에 기존 `3개 책방`, `3개 소식`이 표시됩니다.
- [ ] 흰 화면, 무한 로딩, 오류 팝업이 없습니다.

하나라도 다르면 테스트를 시작하지 말고 화면을 캡처합니다.

## 4. 입력자 로그인과 세션 — #66

1. `소식 입력` 버튼을 누릅니다.
2. 입력자 작업 암호를 입력하고 이동합니다.
3. 책방 목록 화면이 나타나는지 확인합니다.
4. 브라우저를 새로고침합니다.
5. 암호를 다시 묻지 않고 책방 목록이 유지되는지 확인합니다.
6. `로그아웃`을 누릅니다.
7. 방문자 메인 화면으로 돌아오는지 확인합니다.
8. 다시 `소식 입력`으로 로그인합니다.

기대 결과:

- [ ] 올바른 암호로 정상 로그인됩니다.
- [ ] 새로고침 후 로그인 상태가 유지됩니다.
- [ ] 로그아웃 후 작업자 화면에 다시 들어갈 수 없습니다.

## 5. 테스트 책방 만들기

1. `책방 관리`로 이동합니다.
2. 책방 이름을 `[UAT-20260909] 검증책방`으로 입력합니다.
3. 지역과 주소에는 위 표의 테스트 값을 입력합니다.
4. 나머지 필수 항목이 표시되면 테스트용 값을 입력합니다.
5. 저장 버튼을 한 번만 누르고 저장 완료 안내를 기다립니다.
6. `뒤로가기`로 책방 목록에 돌아옵니다.

기대 결과:

- [ ] 저장 중 안내 뒤 성공 안내가 표시됩니다.
- [ ] 목록에 테스트 책방이 한 번만 추가됩니다.
- [ ] 뒤로가기 후 입력한 책방 정보가 사라지지 않습니다.

## 6. 달력 월 이동과 여러 날짜 — #42

1. 발행 월을 `2026년 10월`로 선택하고 테스트 책방을 엽니다.
2. 첫 소식 제목을 `[UAT-42] 달력 월 이동 검증`으로 입력합니다.
3. 장소·상세 내용 등 화면에 표시된 나머지 필수 항목을 테스트 문구로 채웁니다.
4. 날짜 선택 달력에서 `2026년 10월 15일`을 선택합니다.
5. 달력 상단의 `다음 달` 화살표를 한 번 누릅니다. 날짜는 누르지 않습니다.
6. 화살표만 눌렀는데 11월 날짜가 자동 추가되지 않았는지 확인합니다.
7. `2026년 11월 3일`을 선택합니다.
8. `이전 달` 화살표로 10월을 다시 열고 10월 15일이 유지되는지 확인합니다.
9. 11월 3일만 제거하고 10월 15일이 함께 지워지지 않는지 확인합니다.
10. 11월 3일을 다시 추가합니다.

기대 결과:

- [ ] 이전·다음 달 화살표는 달력만 이동시키고 날짜를 자동 선택하지 않습니다.
- [ ] 10월 15일과 11월 3일을 서로 독립적으로 추가·삭제할 수 있습니다.
- [ ] 한 날짜를 삭제해도 다른 날짜는 유지됩니다.

## 7. 장기 전시 기간 — #43

1. 소식을 하나 추가하고 제목을 `[UAT-43] 장기 전시 기간 검증`으로 입력합니다.
2. 날짜 입력 방식에서 여러 개별 날짜가 아닌 `기간`을 선택합니다.
3. 시작일을 `2026년 10월 20일`, 종료일을 `2026년 12월 5일`로 입력합니다.
4. 장소와 상세 내용에 테스트 문구를 입력합니다.
5. 종료일을 잠시 `2026년 10월 19일`로 바꾸고 수동 임시 저장을 누릅니다.
6. 잘못된 날짜 안내가 표시되면 종료일을 다시 `2026년 12월 5일`로 복구합니다.
7. 수동 임시 저장을 누릅니다.
8. 책방 목록으로 나갔다가 다시 들어옵니다.

기대 결과:

- [ ] 시작일과 종료일을 모든 날짜를 하나씩 누르지 않고 입력할 수 있습니다.
- [ ] 재진입 후 두 날짜가 그대로 유지됩니다.
- [ ] 종료일을 시작일보다 빠르게 입력하면 저장되지 않고 정확한 위치를 안내합니다.

## 8. 작성 중 URL 자동 저장 — #45

1. 소식을 하나 추가하고 제목을 `[UAT-45] URL 자동 저장 검증`으로 입력합니다.
2. 날짜·장소 등 화면에 표시된 필수 항목을 테스트 값으로 채웁니다.
3. 신청 링크 또는 관련 링크에 아직 작성 중인 값 `https:/`를 입력합니다.
4. 상세 내용 끝에 `부분 URL 작성 중에도 이 문장은 저장됩니다.`를 입력합니다.
5. 자동 저장 완료 안내가 나타날 때까지 기다립니다.
6. 책방 목록으로 이동할 때 저장 안내가 나오면 `임시 저장 후 이동`을 선택합니다.
7. 같은 책방을 다시 열어 부분 URL과 상세 문장이 모두 남아 있는지 확인합니다.
8. 앞에서 만든 소식에 빠진 필수 항목이 없는지 확인합니다.
9. 아직 URL을 고치지 않은 상태에서 `입력 마무리`를 누릅니다.
10. URL 입력 위치로 이동하고 완료가 차단되는지 확인합니다.
11. URL을 `www.example.com`으로 바꾸고 입력창 밖을 누릅니다.

기대 결과:

- [ ] `https:/`를 작성하는 도중에도 다른 제목·본문의 자동 저장은 성공합니다.
- [ ] 불완전한 URL은 입력 마무리 단계에서만 차단됩니다.
- [ ] 어느 소식의 어떤 URL이 문제인지 표시하고 해당 입력창으로 이동합니다.
- [ ] `www.example.com`은 안전한 `https://www.example.com` 형태로 보완됩니다.

## 9. 사진과 드래그 사용감

1. 테스트 소식 하나에 JPG 또는 PNG 사진을 추가합니다.
2. 가능하면 HEIC 사진도 한 장 추가합니다.
3. 업로드 안내가 끝날 때까지 기다린 뒤 사진과 설명이 표시되는지 확인합니다.
4. 본문 글자를 마우스로 드래그해 선택합니다.
5. 글자 선택 중 소식 카드 자체가 이동하지 않는지 확인합니다.
6. 카드의 전용 `⠿` 손잡이를 끌어 소식 순서를 바꿉니다.
7. 사진도 전용 손잡이로만 순서를 바꿉니다.

기대 결과:

- [ ] 사진이 가운데 정렬된 미리보기로 표시됩니다.
- [ ] 업로드 뒤 나갔다 들어와도 사진과 설명이 유지됩니다.
- [ ] input·textarea의 글자를 드래그할 때 카드 순서가 바뀌지 않습니다.
- [ ] 전용 손잡이를 끌 때만 소식과 사진 순서가 바뀝니다.

사진 업로드가 실패하면 파일 형식·크기와 화면 오류 문구만 기록하고 반복 업로드하지 않습니다.

## 10. 마지막 한글과 입력 마무리 — #44

1. 마지막 소식을 추가하고 제목을 `[UAT-44] 마지막 한글 저장 검증`으로 입력합니다.
2. 필수 날짜·장소·상세 내용을 채웁니다.
3. 상세 내용 마지막에 `신규모집완료`를 천천히 입력합니다.
4. 마지막 글자 `료`를 입력한 직후 다른 곳을 누르지 않고 `입력 마무리`를 누릅니다.
5. 목록으로 돌아온 뒤 같은 책방을 다시 엽니다.

기대 결과:

- [ ] 저장이 끝난 뒤에만 목록으로 이동합니다.
- [ ] 다시 열었을 때 `신규모집완료`가 마지막 글자까지 남아 있습니다.
- [ ] `신규모`, `신규모집완`처럼 일부가 누락되지 않습니다.
- [ ] 책방 상태와 월별 진행률이 `입력 완료`로 바뀝니다.

## 11. 방문자 화면 확인

1. 로그아웃하거나 로그인하지 않은 다른 브라우저에서 Staging을 엽니다.
2. 달력을 `2026년 10월`, `11월`, `12월` 순서로 이동합니다.
3. 테스트 책방과 네 개 소식 제목을 확인합니다.
4. 장기 전시 소식이 10월 20일부터 12월 5일까지의 범위에 표시되는지 확인합니다.
5. 소식 제목을 눌러 상세 내용과 축소 사진을 확인합니다.
6. 가능하면 휴대전화 화면에서 상세 팝업을 스크롤합니다.

기대 결과:

- [ ] 카드에는 책방 이름과 소식 제목이 간결하게 표시됩니다.
- [ ] 장기 전시가 기간 시작·종료 월에 모두 표시됩니다.
- [ ] 상세 팝업을 스크롤할 때 뒤쪽 화면은 함께 움직이지 않습니다.
- [ ] 기존 3개 책방·3개 소식도 그대로 유지됩니다.

## 12. HTML 편집자 로그인과 결과물 — #66

1. 방문자 화면에서 `HTML 편집`을 누릅니다.
2. HTML 편집자 작업 암호로 로그인합니다.
3. HTML 편집자 화면이 열리는지 확인하고 브라우저를 새로고침합니다.
4. 새로고침 후에도 HTML 편집자 화면이 유지되는지 확인합니다.
5. `[UAT-20260909] 검증책방`이 입력 완료 자료로 표시되는지 확인합니다.
6. 개별 HTML 미리보기와 코드 복사를 확인합니다.
7. HTML·사진 묶음을 내려받아 `.html`과 복사용 `.txt`가 모두 있는지 확인합니다.
8. 통합본에 포함할 소식을 선택하고 책방 순서 손잡이가 작동하는지 확인합니다.
9. 로그아웃합니다.

기대 결과:

- [ ] 올바른 암호로 HTML 편집자 화면이 열립니다.
- [ ] 새로고침 후 세션이 유지되고 로그아웃 후에는 접근할 수 없습니다.
- [ ] 입력 완료된 테스트 책방만 HTML 작업 대상으로 표시됩니다.
- [ ] `.txt`의 HTML 마크업을 복사할 수 있고 사진 파일 이름을 구분할 수 있습니다.

## 13. 즉시 중단해야 하는 상황

아래 중 하나라도 발생하면 더 진행하지 않고 `FAIL`로 기록합니다.

- 기존 책방이나 소식이 사라짐
- 저장 성공 안내가 나왔는데 입력 내용이 누락됨
- 마지막 한글이 잘림
- 같은 테스트 책방이 중복 생성됨
- 자동 저장이 반복해서 400·409·500 오류를 표시함
- 사진 업로드 후 깨진 이미지가 저장됨
- 올바른 암호로 로그인되지 않거나 로그아웃 후에도 작업 API에 접근됨
- 화면이 흰색으로 나오거나 로딩이 끝나지 않음

## 14. 결과 전달 양식

아래 내용을 복사해 결과만 채웁니다.

```text
[v1.1 사용자 UAT 결과]
테스트 일시:
브라우저/기기:

1. 시작 상태: PASS / FAIL / BLOCKED
2. 입력자 로그인·새로고침·로그아웃: PASS / FAIL / BLOCKED
3. 테스트 책방 저장: PASS / FAIL / BLOCKED
4. 달력 월 이동·여러 날짜(#42): PASS / FAIL / BLOCKED
5. 장기 전시 기간(#43): PASS / FAIL / BLOCKED
6. 부분 URL 자동 저장(#45): PASS / FAIL / BLOCKED
7. 사진·드래그: PASS / FAIL / BLOCKED
8. 마지막 한글 저장(#44): PASS / FAIL / BLOCKED
9. 방문자 달력·상세: PASS / FAIL / BLOCKED
10. HTML 편집자 로그인·결과물: PASS / FAIL / BLOCKED

만든 테스트 책방 이름: [UAT-20260909] 검증책방
오류가 발생한 단계:
화면에 나온 오류 문구:
추가 설명:
```

모두 `PASS`여도 테스트 자료는 직접 삭제하지 않습니다. 결과를 전달받은 뒤 정확한 테스트 ID와 이름을 대조해 Staging에서만 정리하고, 기존 데이터 수가 테스트 전과 같은지 다시 확인합니다.
